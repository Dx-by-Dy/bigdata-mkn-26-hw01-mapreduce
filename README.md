## Задание 1. Выявление лидеров и пограничных значений в многомерных данных

### Входные данные

Файл в формате CSV. Каждая строка содержит 10 полей, разделенных запятыми:

```csv
row_id,metric_1,metric_2,metric_3,metric_4,metric_5,metric_6,metric_7,metric_8,metric_9
```

| Поле | Тип | Ограничения |
|------|-----|-------------|
| `row_id` | Строка | Уникален. Не содержит пробелов и запятых. |
| `metric_N` | Число с плавающей точкой | Может принимать любое значение. |

### Свойства данных

1. Количество строк: до 10 миллиардов.
2. Количество столбцов: 10 (первый — `row_id`, остальные 9 — числовые показатели).
3. `row_id` уникален для каждой строки.
4. Значения `metric_N` могут повторяться.
5. Ошибки форматирования отсутствуют.

### Задача

Для каждого из 9 числовых столбцов `metric_1` ... `metric_9` определить:

1. Множество `row_id`, которые **однозначно** входят в топ-3 по значению этого столбца (по убыванию).
2. Количество строк, которые **оказались на границе** топ-3 (то есть имеют значение, равное значению 3-го места, но не вошли в топ-3 однозначно).

### Определения

- **Топ-3 по столбцу** — три строки с наибольшими значениями в этом столбце.
- **Однозначное попадание в топ-3** — строка, значение которой строго больше значения строки, занимающей 4-е место (при сортировке по убыванию).
- **Граница топ-3** — строки, значение которых равно значению строки, занимающей 3-е место, но которые не попали в топ-3 однозначно.
- Количество строк на границе **не может быть равно 1**. Если все три места заняты однозначно, количество строк на границе равно 0.

### Пример

Для одного столбца:

```csv
a,10
b,200
c,150
d,150
e,150
```

- `b` — однозначно вошел в топ-3.
- `c`, `d`, `e` — оказались на границе (все имеют значение 150).
- Количество на границе: 3.

### Выходные данные

Формат CSV:

```csv
metric_name,top3_ids,border_count
```

| Поле | Тип | Описание |
|------|-----|----------|
| `metric_id` | Целое число | Номер столбца(1 ... 9). |
| `top3_ids` | Строка | Список `row_id`, разделенных символом `;`. Порядок — по убыванию значения. |
| `border_count` | Целое число | Количество строк на границе топ-3. |

### Требования к результату

1. Для каждого из 9 столбцов — ровно одна строка в выходном файле.
2. `top3_ids` содержит только те `row_id`, которые однозначно вошли в топ-3.
3. `border_count` — количество строк, оказавшихся на границе.
4. Если все три места заняты однозначно, `border_count` равен 0.
5. Порядок строк в выходном файле не регламентируется.

## Задание 2. Обогащение данных о посещениях информацией об устройствах

### Бизнес-контекст

Интернет-магазин хранит **исторический справочник устройств** — он накоплен за годы работы и редко меняется.
Ежедневно в систему поступает **поток событий** о посещениях сайта.
Большая часть посещений совершается с **неизвестных устройств** (не авторизованных),
и только небольшая доля относится к известным устройствам из справочника.

Аналитике нужно обогатить события информацией об устройстве (например, категорией доверия),
но только для тех событий, где устройство известно.
События с неизвестных устройств не интересны и должны быть отброшены.

### Входные данные

**Файл A — справочник устройств (исторический, обновляется раз в сутки):**

```csv
device_id,trust_category
```

| Поле | Тип | Описание |
|------|-----|----------|
| `device_id` | Строка | Уникальный идентификатор устройства (MAC-адрес). |
| `trust_category` | Строка | Категория доверия (например, `trusted`, `suspicious`, `blocked`). |

**Файл B — события за текущий день:**

```csv
event_id,device_id,event_type
```

| Поле | Тип | Описание |
|------|-----|----------|
| `event_id` | Строка | Уникальный идентификатор события. |
| `device_id` | Строка | Идентификатор устройства (MAC-адрес). Может быть пустым или содержать неизвестный ID. |
| `event_type` | Строка | Тип события (например, `view`, `click`, `purchase`). |

### Свойства данных

1. **Файл A:**
   - Количество записей: до **1 миллиарда**.
   - Размер: ~20 ГБ.
   - **Не помещается в память одного узла** (64 ГБ).
   - Обновляется раз в сутки.

2. **Файл B:**
   - Количество записей: до 1 миллиарда в день.
   - Размер: ~100 ГБ.
   - **Доля событий с известным устройством:** менее 5%. Остальные 95% — с неизвестными или пустыми ID.

3. Ошибки форматирования отсутствуют.

### Задача

Для каждого события из файла B определить категорию доверия устройства, если устройство присутствует в справочнике.
События с устройствами, отсутствующими в справочнике, должны быть отброшены.

### Определения

- **Известное устройство** — устройство, присутствующее в справочнике (файл A).
- **Обогащенное событие** — событие, для которого найдена категория доверия.

### Выходные данные

Формат CSV:

```csv
event_id,device_id,event_type,trust_category
```

| Поле | Тип | Описание |
|------|-----|----------|
| `event_id` | Строка | Идентификатор события. |
| `device_id` | Строка | Идентификатор устройства. |
| `event_type` | Строка | Тип события. |
| `trust_category` | Строка | Категория доверия из справочника. |

### Требования к результату

1. Для каждого события, где `device_id` присутствует в справочнике — ровно одна строка.
2. События, где `device_id` отсутствует в справочнике — отброшены.
3. Порядок строк не регламентируется.

## Задание 3. Выявление подозрительных пар переводов за соседние календарные сутки

### Бизнес-контекст

Банк анализирует транзакции клиентов на предмет **отмывания денег**. Одна из распространенных схем — **структурирование** (structuring): клиент разбивает крупную сумму на несколько меньших переводов, чтобы обойти порог обязательного контроля (например, 10 000 долларов).

Если два перевода одного клиента, совершенные **в двух соседних календарных сутках** (например, 1-го и 2-го числа), **в сумме** превышают порог — это подозрительная активность, требующая проверки.

### Входные данные

Файл в формате CSV. Каждая строка содержит четыре поля, разделенных запятыми:

```csv
transaction_id,user_id,amount,timestamp
```

| Поле | Тип | Ограничения |
|------|-----|-------------|
| `transaction_id` | Строка | Уникален. Не содержит пробелов и запятых. |
| `user_id` | Строка | Не содержит пробелов и запятых. |
| `amount` | Число с плавающей точкой | Положительное число. Сумма перевода в долларах. |
| `timestamp` | Строка | Формат `YYYY-MM-DDTHH:MM:SS`. |

### Свойства данных

1. Количество строк: до 10 миллиардов.
2. Количество уникальных `user_id`: не более 100 миллионов.
3. Для каждого `user_id` количество транзакций может быть любым (от 1 до 1000).
4. `transaction_id` уникален для каждой строки.
5. В один день у одного клиента может быть **несколько переводов**.
6. Ошибки форматирования отсутствуют.

### Задача

Для каждого клиента найти все пары переводов, которые:

1. Совершены **в двух соседних календарных сутках** (разница в датах ровно 1 день).
2. **В сумме превышают** порог обязательного контроля.

Порог `T` = 10 000 долларов.

### Ограничение реализации

Для обеспечения пропускной способности **запрещается** использовать вторичную сортировку (secondary sort) для группировки транзакций по датам внутри одного `user_id`.

### Определения

- **Соседние календарные сутки** — две даты, разница между которыми составляет ровно 1 день (например, `2023-10-01` и `2023-10-02`).
- **Пара переводов** — комбинация `(transaction_id_1, transaction_id_2)`, где оба перевода принадлежат одному клиенту.
- **Подозрительная пара** — пара переводов одного клиента, совершенных в соседние календарные сутки, сумма которых превышает порог `T`.
- Порядок переводов в паре не важен: пара `(t1, t2)` эквивалентна паре `(t2, t1)`.

### Пример

Для одного клиента:

```csv
t1,u1,6000,2023-10-01T10:00:00
t2,u1,5000,2023-10-02T09:00:00
t3,u1,7000,2023-10-02T14:00:00
t4,u1,3000,2023-10-03T11:00:00
```

При пороге `T = 10000`:

- Пара `(t1, t2)` — соседние сутки (01.10 и 02.10), сумма 11000, превышает порог. **Подозрительная.**
- Пара `(t1, t3)` — соседние сутки (01.10 и 02.10), сумма 13000, превышает порог. **Подозрительная.**
- Пара `(t2, t3)` — одна дата (02.10), **не рассматривается**.
- Пара `(t1, t4)` — разница 2 дня, не рассматривается.
- Пара `(t2, t4)` — соседние сутки (02.10 и 03.10), сумма 8000, не превышает порог.
- Пара `(t3, t4)` — соседние сутки (02.10 и 03.10), сумма 10000, не превышает порог (требуется строго больше 10000).

Результат:

```csv
u1,t1,t2,11000
u1,t1,t3,13000
```

### Выходные данные

Формат CSV:

```csv
user_id,transaction_id_1,transaction_id_2,total_amount
```

| Поле | Тип | Описание |
|------|-----|----------|
| `user_id` | Строка | Идентификатор клиента. |
| `transaction_id_1` | Строка | Идентификатор первого перевода. |
| `transaction_id_2` | Строка | Идентификатор второго перевода. |
| `total_amount` | Число с плавающей точкой | Сумма двух переводов. |

### Требования к результату

1. Для каждой подозрительной пары — ровно одна строка в выходном файле.
2. Пара `(t1, t2)` и пара `(t2, t1)` считаются одной и той же парой. В выходном файле должна быть только одна из них.
3. `total_amount` — точное значение суммы.
4. Порядок строк в выходном файле не регламентируется.
